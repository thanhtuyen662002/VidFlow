# M8.4: renderer/preload contract

The single renderer contract is renderer/src/api.ts. It imports only types
from src/types.ts. getApi() reads window.vidflow; App obtains this client and
passes it to the project, Bible, reference and script gate views. The older
renderer api/client.ts and api/contract.ts paths are compatibility exports.
src/app/renderer-contract.ts is also a type-only compatibility export.

The existing src/app/preload.cjs already exposes projects.list/create,
bible.get/update, references.list/add/remove and script.getGate/approve/skip.
Their exact existing signatures are preserved, including gate.options,
gate.lockReason, approve(projectId, { optionId, comment }) and
skip(projectId, { reason }). The fallback variant contract requested for an
absent preload does not apply. No new main-process handlers or core modules
are introduced in this revision.

Core integration must supply the existing gate contract. The UI directly
binds disabled to canApprove/canSkip, renders returned scores, notes, risks
and lock reasons, and rereads the gate after a successful decision. It does
not derive permissions from scores, risks or status. A skip reason must
contain non-whitespace text; the original reason is passed to the API.
References may be submitted with a description without an image path; the
core remains responsible for domain validation and path safety.

Tests follow the pinned node --test runner, using node:test mock.fn rather
than Vitest/vi.fn or additional testing packages. JSX is compiled by Vite
inside the .test.ts harness so Node 24 can discover and run it without a TSX
loader or changes to the test script. jsdom receives window.vidflow before
each render; App has no injectable alternate API. Tests cover project creation,
reference mutations, Bible editing, approval, lock flags despite high scores,
risk display, skip reasons, refreshed state and API errors.
