# M10.2: source import and segmentation

The core API is exported from `src/motion/index.ts`. All functions receive the existing `DatabaseSync` connection as their first argument, matching repository conventions. The caller owns and closes this connection.

- `importSourceVideo(db, { projectId, filePath, rightsConfirmed, sceneThreshold?, maxSegmentSec?, minSceneSec? })` returns a `Promise<SourceVideo>` and creates its initial segments. `filePath` is relative to the project data directory, matching existing asset path rules. Stage input files there before calling this API.
- `segmentSourceVideo(db, sourceVideoId, options?)` returns a `Promise<SourceSegment[]>`.
- `setOwnerCutPoints(db, sourceVideoId, cutPointsSec)` validates, sorts, deduplicates and snaps owner cuts, then synchronously replaces segments.
- `listSegments(db, sourceVideoId)` and `getSourceVideo(db, sourceVideoId)` read persisted records.
- `RightsNotConfirmedError`, `SourceVideo`, `SourceSegment` and `SegmentOptions` are exported.

Migration 16, **Source videos and scene segments**, adds the two tables. Defaults are scene threshold 0.3, minimum scene length 0.5 seconds and maximum segment length 8 seconds. M3 currently exposes numeric fps, so the new table also stores numeric fps. Segment ends use exclusive frame boundaries. The final boundary is the nearest frame to the probed duration, with a maximum rounding error of half a frame. Splitting uses an integer frame limit and evenly distributes frames, preserving complete contiguous coverage.

Owner cuts are stored separately as JSON: null means automatic detection, while an empty array explicitly means one owner-defined scene. Re-segmentation reloads this value after asynchronous detection so a concurrent owner edit wins. Owner scene starts have origin `owner`; additional starts inserted to meet the length limit have origin `split`.

Imports verify rights before accessing the filesystem or database. Copies use exclusive creation and hash plus UUID names. Same-project duplicate hashes reuse their existing record without copying or segmenting again. Original audio, when present, is copied without transcoding into a unique `exports/*-source-audio.mka` file through M3; this location follows M3's existing output restrictions. Source copies remain in `sources/`. Failed imports remove only their newly created files. No UI, MCP, CLI or other M10 task is included.

Tests generate media at runtime under a temporary VIDFLOW_HOME and clean it up, including after skips. The 30-second sample uses testsrc, then color with static drawtext, then mandelbrot, as M10.md requires. Before building it, the test checks drawtext availability through ffmpeg -filters using M3's runFfmpeg helper and its existing binary resolver (VIDFLOW_FFMPEG, then PATH). If drawtext is missing or rendering fails because of fontconfig or font errors, the test skips with a stated reason; it does not substitute plain color. Scene detection runs through the core import API at threshold 0.3 and asserts exactly two cuts within 0.2 seconds of 10 and 20 seconds. The media integration test also skips with a reason when either tool is missing; rights, frame partition, transaction rollback and dependency-graph tests run independently of media tools.
