# M9.4: Cập nhật kênh dev

Không cần dependency mới. Lõi `src/app/updater.ts` dùng Node built-ins và nhận cấu hình, fetcher, thư mục, phiên bản hiện tại, callback xác nhận và callback cài đặt qua dependency injection.

## Cấu hình và manifest

Dùng `McpSettingsStore` hiện có (SQLite, bảng `app_mcp_settings`). Khóa `updates` mặc định là `{ "channel": "dev", "sourceUrl": "" }`; dữ liệu cũ thiếu khóa này cũng dùng mặc định đó. Chủ sở hữu cấu hình bằng `configureUpdates(store, manifestUrl)` trong `src/app/mcp/settings.ts`, giữ nguyên cấu hình MCP khác. URL trống nghĩa là chưa cấu hình, không có URL production hardcode.

`sourceUrl` trỏ trực tiếp tới JSON của kênh dev, ví dụ:

```json
{
  "version": "0.2.0-dev.3",
  "url": "VidFlow-Setup.exe",
  "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "size": 123456,
  "releaseNotes": "Các thay đổi của bản dev"
}
```

`file` có thể thay cho `url`; URL tương đối được giải theo URL manifest. `size` (byte) và `releaseNotes` không bắt buộc. Chỉ HTTP(S), không URL chứa credentials, không tự theo redirect. Nguồn phát hành phải cung cấp liên kết artifact trực tiếp. CI phát hành từ main khi xanh là trách nhiệm pipeline phát hành, ngoài task này.

So sánh SemVer gồm prerelease số/chữ và build metadata; chỉ báo bản mới hơn. Manifest tối đa 1 MiB; tải artifact tối đa kích thước khai báo hoặc 4 GiB khi thiếu size. Mỗi HTTP request có hạn 120 giây.

## Vòng đời và xác nhận

Main chỉ kích hoạt khi `app.isPackaged` hoặc `VIDFLOW_ENABLE_UPDATES=1`. Khi có URL, startup chỉ kiểm phiên bản. Registry dùng chung IPC (`update:check`, `update:download`, `update:status`, `update:install`) và MCP (`update_check`, `update_download`, `update_status`, `update_install`), mọi lệnh nhận `{}`. IPC giữ kiểm tra sender hiện có. Không nhận tham số xác nhận từ client; callback dialog main là nguồn xác nhận duy nhất.

Tải vào `<VIDFLOW_HOME>/updates/update-<uuid>.exe.part`, tính SHA-256 trong stream, kiểm kích thước rồi mới rename `.exe`. Lỗi checksum trả `CHECKSUM_MISMATCH`, xóa file tạm và không sẵn sàng cài. Lỗi HTTP/timeout/size cũng dọn file tạm. Trạng thái `downloaded` nghĩa là file đã xác minh và đang chờ xác nhận. Lõi không có callback hoặc callback trả false thì giữ trạng thái này.

Lệnh cài luôn mở dialog tiếng Việt với phiên bản, release notes, nút “Cài và khởi động lại” / “Để sau”; mặc định và Escape đều là để sau. Sau chấp thuận, kiểm lại checksum trên đĩa, spawn Windows installer detached, không shell, không silent flags; chỉ quit sau sự kiện spawn thành công. Installer NSIS tương tác chịu trách nhiệm hoàn tất cài đặt và mở lại ứng dụng. Không tự cài nền; lệnh cài lặp/concurrent bị từ chối.
