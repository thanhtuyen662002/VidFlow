# M8.5: storyboard, render, take, export and settings

The renderer extends the existing React app and `window.vidflow` sandbox preload.
No dependency manifests or Flow/render/edit/media/prompt modules were changed.
The service registry remains the single source of IPC and MCP schemas.

## Screens

- Storyboard lists shots and compiled prompts, approves the board, or requests
  revision by returning it to draft. Successful script approval fills the version
  field; an existing approved version can also be entered explicitly.
- Render displays service plan/shot states, progress notifications, committed
  credit usage and budget limit. Cancel remains accessible during render. Redo
  first displays the core's affected scene IDs and estimate, then sends a separate
  accept/reject decision. Start render consumes accepted rework through core.
- Takes forwards the chosen take and numeric in/out values to `take.select`.
  Validation belongs to the service; its returned error is displayed.
- Edit builds the timeline, selects 16:9 or 9:16, exports video or CapCut, and
  builds a publish package from exported videos, a cover and description model.
  The mixed-audio path and cover remain project-relative inputs validated by core.
- Settings lists account status and credit, edits the project budget, toggles MCP,
  and creates/rotates/revokes its credential. Token values are never returned or
  shown. The UI names the private storage location instead.

`needs_owner` displays **Cần chủ sở hữu**, a login/verification hint and
`data-testid="account-needs-owner"`. Render and settings also have owner banners.
Service account DTOs retain only id/label/status/remainingCredits. Settings DTOs
contain enabled/credentialConfigured/credentialLocation. Renderer public-data
filtering additionally removes secret fields from older or fake preload replies.
No raw account/session objects are rendered.

## Added IPC/service methods

Preload exposes each command below as group.method(input), invoking the same
name with a colon separator. Inputs are declared in `src/types.ts`; renderer
return contracts are in `renderer/src/workflow.ts`.

| Method | Delegation |
| --- | --- |
| storyboard.reject({storyboardId}) | New `rejectStoryboard(db, board)` in src/script/storyboard.ts; uses existing current-board guard and persistence, clears approval |
| render.cancel({planId}) | AbortController for the active run; existing `runRenderPlan({signal})` consumes cancellation, `getRenderPlan` returns status |
| render.redo({planId,sceneId}) | `requestSceneRework(db, planId, sceneId, {})` |
| render.decideRedo({requestId,accept}) | `decideRework(db, requestId, accept)` |
| budget.get({projectId}) | `projectCommittedCredits(db, projectId)` and `getProject(db, projectId)` |
| budget.set({projectId,limit}) | `updateProject(db, projectId, {budget: limit})`, then the same budget read |
| settings.get({}) | `McpSettingsStore.getSettings()`, projected to public DTO |
| settings.configure({enabled}) | `configureMcp(store, enabled, existingPort)` |
| settings.rotate({}) | `configureMcp(store, true, existingPort, true)` |
| settings.revoke({}) | New `revokeMcp(store)` delegates to `getSettings/saveSettings`, disables MCP and removes credential |

Rework, budget and settings targets were newly integrated with the registry;
their implementations and exact signatures were inspected directly. No unknown
or guessed delegation targets remain. Storyboard rejection and credential revoke
are explicitly added operations in existing allowed modules, not placeholder
imports. Cancel is cooperative: the current driver operation finishes before the
orchestrator observes its signal at the next take boundary. Committed usage
includes credit reservations, as defined by the existing budget core.

Existing methods remain: storyboard.generate/approve -> generateStoryboard /
approveStoryboard; render.enqueue/run/status -> approvedStoryboardPlan /
runRenderPlan / getRenderPlan; take.list/select -> listByScene /
resolveSelection + setOwnerOverrideAndRefresh; edit.assemble/capcut/export ->
buildTimelineFromSelectedTakes / buildCapcutDraft + writeCapcutDraft / exportFinal;
export.package -> buildPublishPackage. UI makes no budget, scoring, prompt or
state-transition decisions.

Electron shares the service's MCP settings store with its lifecycle. An explicit
store passed to startElectron is still honored and bound into the service, so
Settings mutations reach the running server. Existing exported signatures accept
the same inputs; additions are optional or additive.

## Tests and verification

`test/renderer/app.test.ts` uses the existing node:test + Vite + jsdom harness.
The new `workflowFake.ts` supplies an in-memory `window.vidflow`, deferred render
completion, progress subscription and call recording. The full test drives:
create project -> add reference -> approve script -> approve storyboard -> render
(running and finished) -> choose take and interval -> build -> export 9:16 video
and CapCut -> publish package. It asserts DOM state, mutation ordering and inputs.
Further tests cover owner badge/hint, secret strings absent from textContent and
innerHTML across all tabs and credential rotation, budget edits, service interval
errors, storyboard rejection, cancel, redo approval and subscription cleanup.

`test/service.test.ts` proves account/settings DTOs omit private fields and the
stored credential value. Existing service and MCP full-flow tests now exercise
all newly registered methods and retain the exact registry command-set assertion.
The preload contract and workflow-client tests remain compatible.

Run on Node 24 in the complete checkout:

```text
node --test --test-isolation=none test/renderer/app.test.ts test/renderer/workflow-client.test.ts test/renderer/preload-contract.test.ts test/service.test.ts test/electron-ipc.test.ts test/mcp-flow.test.ts
npm test
```

Tests were not run in this revision; no passing test result is claimed. Static
`node --check` was used for changed TypeScript without JSX. Agent Forge must run
the jsdom and integration suites with the repository's locked dependencies.
