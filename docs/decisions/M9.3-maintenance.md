# M9.3 — Sao lưu, khôi phục và dọn take

Triển khai trong `src/service/archive.ts`, `src/service/maintenance.ts`; kiểm thử tại `test/maintenance.test.ts`. Không thay dependency, package.json, lockfile hay migration. Đã đọc PLAN, M9, triển khai và quyết định M9.1/M9.2.

## API

```ts
import { createMaintenanceService } from '../../src/service/maintenance.ts';
const maintenance = createMaintenanceService(db); // mặc định VIDFLOW_HOME
await maintenance.backup('archives/du-an.vfb');
await maintenance.restore('archives/du-an.vfb', thuMucDuLieuMoi);
const plan = maintenance.listUnselectedTakes(projectId);
// Hiển thị plan.takes, plan.totalSize cho chủ sở hữu.
// Chỉ sau khi chủ sở hữu xác nhận đúng danh sách này:
maintenance.deleteTakes(plan, plan.confirmation);
```

API thấp hơn: `backup(sourceDir, backupFile, { onSkip? })`, `restore(backupFile, targetDir, { allowNonEmpty? })`, `readBackupManifest(backupFile)`, `listUnselectedTakes(db, projectId, dataDir?)`, `deleteTakes(db, plan, confirmation?, dataDir?)`. Import từ maintenance hoặc archive tương ứng. Đây là API dịch vụ cục bộ tối thiểu được phép trong yêu cầu task. Tích hợp registry MCP, preload và nút UI là phần tiếp theo; task này không thêm endpoint xóa tự động. Adapter phải yêu cầu chủ sở hữu duyệt danh sách trước khi truyền confirmation; token là bằng chứng ràng buộc danh sách, không phải xác thực danh tính con người.

Khôi phục bắt buộc khác thư mục nguồn và thư mục dữ liệu đang dùng; cũng từ chối thư mục con của nguồn. Mặc định đích phải trống. `allowNonEmpty: true` cho phép ghép thêm file nhưng luôn từ chối ghi đè. Kiểm tra toàn bộ manifest trước khi ghi dữ liệu, ghi vào staging, xác minh hash và gzip hoàn chỉnh rồi mới xuất file. Nếu lỗi hash/traversal/truncation thì không xuất file dữ liệu. Lỗi I/O trong bước xuất cuối có thể để lại một số file đã xác minh; không ghi đè file có sẵn. Không tự sửa đường dẫn tuyệt đối trong SQLite/JSON: snapshot giữ nguyên dữ liệu nghiệp vụ; đổi root hoạt động của ứng dụng sau restore cần luồng chuyển thư mục riêng.

## Định dạng VIDFLOWBAK1

Một gzip stream, bên trong theo thứ tự:

1. UTF-8 `VIDFLOWBAK1\n`.
2. Số nguyên không dấu 32-bit big-endian: độ dài manifest (tối đa 16 MiB).
3. JSON UTF-8: `{ version: 1, createdAt, sourceDir, files: [{ path, size, sha256, mode }] }`.
4. Nội dung nguyên bản từng file theo thứ tự manifest, không separator; `size` xác định biên.

Path dùng POSIX, tương đối. Từ chối absolute path, `..`, backslash, Windows ADS/device/alias, entry trùng, entry bị loại trừ và đường dẫn thoát qua symlink. Không có symlink trong archive. Tên sourceDir chỉ phục vụ chặn restore về nguồn. Không lưu thư mục rỗng. Media được đọc/ghi theo stream; bộ đệm restore tối đa 64 KiB cho nội dung file. SHA-256 kiểm tra cả lúc sao lưu để phát hiện file bị thay đổi. Tạm dừng render/chỉnh sửa khi tạo bản sao để có snapshot nghiệp vụ nhất quán giữa SQLite và media; SQLite riêng được snapshot nhất quán kể cả dữ liệu WAL. File archive đã tồn tại luôn bị từ chối.

## Danh sách loại trừ chính xác

`BACKUP_EXCLUSIONS` và `isBackupExcluded` được export, áp dụng không phân biệt hoa/thường cho từng thành phần đường dẫn ở mọi độ sâu:

Ngoài ra bỏ chính file archive đầu ra, đường dẫn do `accounts.secret_ref` chỉ tới, mọi symlink và file không phải regular file. Symlink có thông báo tiếng Việt qua onSkip, mặc định console.warn; không in đường dẫn có thể chứa dữ liệu nhạy cảm. `evidence`/`screenshots` chứa ảnh phiên trình duyệt nên loại cả thư mục.

Repo chưa có secret store tổng quát: `repo/accounts.ts` cấm lưu raw secret và chỉ giữ `secret_ref`; MCP lưu token trong bảng `app_mcp_settings`. Sao lưu dùng node:sqlite backup tạo snapshot riêng, xóa toàn bộ app_mcp_settings, đặt accounts.secret_ref=NULL, secure_delete và VACUUM để không còn byte bí mật ở trang trống. Không sửa DB nguồn. DB khôi phục vì thế có hash bằng snapshot đã làm sạch, không bằng DB nguồn chứa bí mật; các file dữ liệu khác giữ nguyên từng byte. Giả định secretRef là khóa vault opaque hoặc đường dẫn file/thư mục tương đối với dataDir hay tuyệt đối; đường dẫn tương ứng được bỏ. Không có backend vault khác trong checkout. Không thể nhận diện bí mật do người dùng tùy ý đặt trong nội dung file nghiệp vụ với tên không liên quan; chính sách này bao phủ các vị trí bí mật được định nghĩa trong repo.

## Dọn take

Đọc `takes.selected`, selections, M6 render_reviews suggestion/owner_override (kể cả fallback của partial override), scene_start_frames, timeline_clip (take_id, source_path, source_asset_id), JSON trong exports (CapCut/publish). Giữ cả tham chiếu lịch sử để bảo toàn draft/export cũ. JSON lỗi/quá 16 MiB hoặc symlink ở exports làm thao tác thất bại an toàn. Chỉ regular file dưới `<project>/renders/`, nằm trong dataDir, không có symlink/hardlink mới là ứng viên. Không xóa thư mục, ảnh refs, frame, export hay file ngoài dự án. Take có đường dẫn trùng file được chọn cũng được giữ.

Plan gồm projectId/dataDir, takeId, sceneId, path, size, sha256, tổng byte và confirmation HMAC-SHA256. Khóa chỉ tồn tại trong tiến trình; khởi động lại phải lập plan mới. Xóa thiếu/sai xác nhận, danh sách sửa/khác, hash file đổi hoặc lựa chọn đổi đều bị từ chối trước bất kỳ unlink nào. `BEGIN IMMEDIATE` giữ selection writer SQLite bị khóa trong lúc đọc lại plan và xóa đồng bộ. Metadata take giữ lại làm lịch sử; file đã mất không được liệt kê lần sau. Lỗi I/O khi unlink có thể xóa được một phần danh sách đã xác nhận; SQLite không thể rollback filesystem. Không hỗ trợ tiến trình khác sửa trực tiếp media trong lúc dọn; cần tạm dừng chúng.
