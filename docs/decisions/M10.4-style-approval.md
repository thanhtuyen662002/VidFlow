Read the complete `docs/milestones/M10.md` and PLAN section 16. M10.2 and M10.3 are present: migrations 16/17, `source-import.ts`, `subjects.ts`, and the existing motion compiler. Core lives directly in `src/`, with motion in `src/motion/`; tests live in `test/`.

- M10 does not prescribe preset columns, approval status names, price amounts, or rounding. Migration 18 supplies the requested minimum columns and pending/approved/rejected states. Prices in the supplied config are editable estimates, not verified provider prices.

## Configuration and migration

`src/motion/style-presets.json` is the source of truth for structured presets and pricing. Its runtime JSON schema is exported as `MOTION_PRESET_SCHEMA` from `preset-config.ts`, using the existing schema validator. Unknown fields, missing fields, wrong types, negative limits/prices, empty lists and duplicate preset keys fail clearly. Presets include key/name/version, faceless flag, style, fragments, forbidden and required clauses, disclosure and reference limit.

`018-style-migration.ts`, registered in `src/migrations.ts`, creates `motion_presets` and `motion_style_approvals`. The existing transactional, forward-only user_version runner makes repeated migration idempotent. Sync upserts presets by stable key; removed presets are marked inactive to preserve history. SHA-256 hashes use canonical sorted object keys.

## APIs and credit calculation

- `loadStylePresets(path?: string | URL): MotionPresetConfig`
- `syncMotionPresets(db: DatabaseSync, config: MotionPresetConfig): void`
- `compileMotionPrompts(analysis: readonly AnalyzedMotionSegment[], mapping: readonly MotionMapping[], preset: MotionPreset, bible: CompilerBible)` returns `{ segmentId, prompt, references }[]`.
- `estimateMotionCredits(segments: readonly SourceSegment[], pricing: MotionPricing): number`
- `new MotionStyleService(db, { configPath?, bibleFor? })`
- `createStylePreview(sourceVideoId: string, presetKey: string): StyleApproval`
- `approveStyle(sourceVideoId: string, approver: string): StyleApproval`
- `getStyleApproval(sourceVideoId: string): StyleApproval | undefined`
- `assertStyleApproved(sourceVideoId: string): void` is the M10.5 pre-enqueue guard. Consumers must use this API rather than trusting a raw persisted status.

Compilation uses existing M2 reference expansion, deterministic segment/subject ordering, reference kind then ID then image/name ordering, and lexical image selection before the configured limit. It does not mutate input or read filesystem, environment, locale, time or randomness. Code always injects the AI disclosure; the faceless flag always injects the mandatory faceless clause regardless of config fragments or contradictory analysis.

Estimate = `sum(ceil((end_sec - start_sec) * creditsPerSecond) * variants)`. Prices and K (`pricing.variants`, supplied default 2 from M10) come from JSON. Cost rounds upward per attempt, before multiplying K; safe integer overflow and invalid prices/durations fail. Preview stores the estimate while pending. Approval without a current estimate fails. Preset, pricing, Bible/reference registry, analysis, segment or mapping changes invalidate approval on the next service check, clear the old estimate and require a new preview and owner approval.
