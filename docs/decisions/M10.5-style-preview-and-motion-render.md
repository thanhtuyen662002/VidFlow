# M10.5: visual preview and motion render

Supersedes the dependency diagnosis in `M10.5-prerequisite-blocked.md`.
`awaiting-M10.5` is the intended M10.4 hand-off. M10.5 completes the
style-transformed image through M10.1 image mode, crops the Flow logo and writes
an original/transformed side-by-side comparison under the project's `renders/`.
The ready preview stores paths, SHA-256 hashes and an AI-generated declaration.
The existing `approveStyle(sourceVideoId, approver)` still accepts text approval;
`approvedWithVisualPreview` records whether the image preview was ready at approval.

`motion` is a RenderJob kind in the existing M6 dispatcher. It must use the same
SQLite storage, account selection, claim/retry loop and budget accounting: a
second queue would break ordering, credit reservations and restart recovery.
Migration 19 adds a SourceSegment foreign key, JSON state and unique segment and
operation keys to `render_jobs`; it creates no queue or state table.
`createMotionDispatcher` configures the existing scheduler with `motionCoordinator`.
Ordinary schedulers leave motion jobs alone. Enqueue and worker gates validate
the current style approval and the compiled input hash.

Each segment records scene/order, command reference, generation, finished steps,
Flow operation IDs, variants and selection. Internal image/video operation rows
use the same RenderJob storage, never compete for scheduler claims, and are
uniquely keyed by parent/generation/step. M10.1 commits downloaded paths with the
credit charge so a restarted worker can reuse a completed paid operation even
before the parent has saved its next checkpoint. Unfinished operations retry
using fresh output paths. No original output is overwritten.

Use `completeVisualPreview`, then the unchanged style approval API,
`enqueueMotionJobs`, and `createMotionDispatcher(...).runUntilIdle()`.
The dispatcher recovery entry point assumes the old process has stopped; callers
must not open a second recovery worker over a live worker. A replacement worker
recovers abandoned motion claims, skips done segments and reloads every substep.

Before dispatch the coordinator checks the remaining project estimate through
M6 budget helpers. Video estimates use M10.4's per-segment rounded configured
prices and variant count. Fallback adds two image estimates (configurable via
`fallbackImageCredits`, default 4 each). Parent reservations cover the unspent
estimate; actual internal operation charges are counted once by M6.
Insufficient allowance persists `awaiting_budget_approval`, displayed as
“chờ duyệt ngân sách”; `approveMotionBudget` accepts the new total project limit
and resumes dispatch.

Within a source scene the selected predecessor's last frame is extracted and
cropped, saved under `renders/`, hashed and uploaded as the next start frame.
The two segment states store identical outgoing/incoming hashes. Scene cuts
break the chain. `selectVariant(db, segmentId, variantId)` keeps owner choices
and invalidates downstream chain inputs; a running successor prevents changing
the upstream choice. Invalidated successors require `approveMotionRerender`
before another paid generation. Old variants and source files are retained.

`frames_then_video` checkpoints first-frame generation/crop, then last-frame
generation/crop, then video edit with both endpoints. A chained predecessor's
cropped frame remains the authoritative video start input. Image operations
still run in the required order, and operation records are readable in state.

Cropping is lossless spatial cropping with no resize, blur, fill or watermark
removal. The fixture geometry places the Flow logo in the bottom 10% and the
separate AI marker at the upper left. M10.1's legacy white rectangle remains the
Flow logo fixture; an explicit AI rectangle is added for preservation checks.
Production geometry and real selectors still require owner calibration as
documented by M10.1. AI disclosure is retained in preview/variant metadata and
derived-image metadata. All motion downloads, clips, frames and comparisons
are confined to the project's `renders/` tree.

Added offline tests cover approval gates, default selections, hash chaining,
scene boundaries, budget approval, fallback order, database reopen/recovery,
owner changes and image preview. The M10.1 fake-page integration also compares
decoded AI-marker RGB bytes before/after the actual crop. Browser/media-dependent
tests skip with a reason when their tools are absent. Per task instructions no
tests were executed locally; M10.4 tests were not modified.
