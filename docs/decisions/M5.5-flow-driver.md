# M5.5 Flow driver

Implemented in `src/flow/driver.ts`, using the existing M5 account status API,
queue lookup, credit ledger, selectors, M5.2 redaction and evidence writer.
No replacement filter or database was introduced. The supplied M5 document
contains the milestone contract but no separate M5.1–M5.5 subsections.

`FlowDriver.runJob(job, ctx): Promise<FlowJobResult>` returns:

```ts
type FlowJobResult =
  | { kind: 'completed'; files: string[]; creditsBefore: number; creditsAfter: number; creditsCharged: number }
  | { kind: 'rejected'; reason: string; rawMessage?: string }
  | { kind: 'out_of_credits'; creditsSeen?: number }
  | { kind: 'verification_required'; detectedBy: string; url: string }
  | { kind: 'failed'; error: string; retryable: boolean };
```

The caller supplies and owns a browser context. `launchFlowContext` uses
Chromium persistent contexts under the configured external `profiles/<accountId>`
directory and rejects profiles inside the checkout. A context is left open on
verification; the account becomes `needs_owner`. Queue completion/rejection/release
remains the responsibility of the worker that owns its claim; this driver does
not impersonate a queue worker. The caller must not concurrently use one context
for several jobs.

All page operations are in ActionRecorder. It checks challenges before actions
and on each result poll, and emits a `read / verification-detected` entry before
the hard stop. Logs contain symbolic targets only. Input values and DOM contents
are omitted from evidence; the existing filtered `saveNote` writes a generic
failure note. Raw Playwright error messages are never returned or persisted.

`credits.chargeJob` is an additive API: a transaction checks the job ID before
appending a negative credit amount. Existing APIs and ledger sign conventions
are unchanged. A job with an existing ledger entry returns a non-retryable
`failed` result before browser actions, preventing another paid generation.
An existing original take is never overwritten. There is still a crash window
between an external site's charge/download and the local ledger commit;
automatic reconciliation of that window is outside this task.

Browser tests cover successful download and a single ledger charge on retry,
policy reason, no credit, challenges initially and after generate, action sequence
checks after detection, and log/evidence omission of private input. They must
still be executed in the provisioned Agent Forge environment with Chromium.

The workspace has no package manifest, dependency tree, Git metadata or
`.gitignore`. The task's output restriction permits new files only under the
listed context directories, so no root `.gitignore` was created. The complete
checkout must retain M5.2's profile/evidence ignore rules.

Real Flow selectors remain intentionally unconfigured and have not been tested.
The owner must calibrate them manually using the existing selector selftest.
No claim is made that this driver works against the real Flow site.
