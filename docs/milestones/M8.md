# M8: Giao diện Electron và máy chủ MCP

## goal
Cài đặt `docs/PLAN.md` mục 12, gồm hai phần.

**Ứng dụng Electron + Vite + React**
- Ngôn ngữ: tiếng Việt mặc định, có tiếng Anh.
- Các màn hình: Dự án, Thư viện tham chiếu, Bible, Xưởng kịch bản, Storyboard, Hàng đợi render, Bảng so sánh take (chọn in/out bằng thanh trượt), Timeline, Tài khoản & credit, Cài đặt (vùng logo, LUT, mặc định model).
- Giao diện chỉ gọi lõi qua IPC có kiểm tra dữ liệu.

**Máy chủ MCP**
- Streamable HTTP, chỉ nghe trên 127.0.0.1.
- Mặc định tắt; khi bật, mọi yêu cầu phải có token Bearer.
- Từ chối mọi yêu cầu có `Origin` và giới hạn kích thước yêu cầu.
- Cung cấp đủ các công cụ liệt kê ở mục 12.
- Có hướng dẫn kết nối cho Claude Code và Codex.

## acceptance_criteria
- Có thể đi hết một dự án trên giao diện, chạy với Flow giả lập và LLM giả lập: tạo dự án, thêm tham chiếu, duyệt kịch bản, duyệt storyboard, render, chọn take, xuất.
- Cũng làm được cùng luồng đó chỉ bằng các công cụ MCP.
- MCP từ chối yêu cầu không có token, sai token, có `Origin`, hoặc khi đang tắt. Không công cụ nào trả về cookie hay token.
- `npm run package:win` tạo ra bộ cài Windows.

## testing_requirements
Test bằng `node --test` cho IPC, cho MCP (HTTP thật trên một cổng tạm), và kiểm thử giao diện bằng jsdom hoặc Playwright với các API giả lập.

## non_goals
- Truy cập từ xa (ngoài 127.0.0.1).
- Ký số bộ cài.

## technical_constraints
- Lõi tái dùng đúng các module của M1–M7.
- Trong giao diện không có logic nghiệp vụ trùng lặp với lõi.

## M8.4: React renderer

The Vietnamese renderer reads core permissions, options, scores, comments and risk warnings through script.getGate. Approval calls script.approve with scriptId/versionId; script.override and script.skip require an owner reason. Mutations fetch the gate again. Eligibility checks are shared with core approval, never calculated in the renderer.

MCP and IPC derive all commands and schemas from the same service registry, including bible.get, reference.remove, script.getGate and script.skip. The end-to-end service and MCP flows invoke every registered command and retain the exact command-set assertion through packaging.

The node:test/jsdom harness installs browser globals before importing react-dom/client and App. It resolves React.act, falls back to react-dom/test-utils, and uses flushSync plus DOM polling when act is unavailable. React and react-dom are locked to matching 19.3.1 versions.

Local verification: the preload contract test passes with test isolation disabled. Full execution is limited by sandbox spawn EPERM, missing src/redact.ts in the supplied workspace, and absent installed React/jsdom/Vite dependencies.

M8.4 reload revision: the renderer uses one stable preload client directly. Each panel reports preload errors locally. Initial reads use awaited handlers without cleanup flags. ProjectPanels is keyed by project id, so a response from a previously selected project belongs to the old component instance.

Reference add/remove await the mutation and then references.list; the library renders the exact returned list, including @ followed by name. Bible and project creation likewise await their matching reads. Gate approve, skip and warning override await the mutation and then script.getGate, rendering status and permissions directly from that response. Data is cleared at the start of mutations, and loading is cleared in finally on success or failure. No reload counter, debounce, computed eligibility or IPC contract change was introduced.

The existing approval assertion requires exactly { scriptId, versionId }; the core ScriptApprovalInput has no comment field. This revision preserves that contract and all existing test expectations. Required and non-whitespace skip reasons remain form validation.

Regression coverage adds a list response that differs from the add response, plus a rejected gate refresh that must clear loading and display the error without stale gate data.

Verification: node --test --test-isolation=none test/renderer/app.test.ts test/renderer/preload-contract.test.ts passed the preload contract test; the renderer suite could not load because React is not installed (ERR_MODULE_NOT_FOUND). npm test could not execute test files because the sandbox rejects child process creation (spawn EPERM). No dependency manifest or existing test expectation was changed.

## M8.5: storyboard, render, takes, export and settings

Implemented the five Vietnamese workflow panels through the existing sandbox
preload and shared service registry. Added storyboard rejection, cooperative
render cancel, core rework estimate/approval, committed budget read/update and
MCP configuration/credential actions. Needs-owner accounts have a visible
`account-needs-owner` badge and action hint. Account/settings DTOs omit secrets;
MCP credentials stay in the private settings store shared with Electron lifecycle.

The node:test/jsdom suite now drives project creation through reference/script /
storyboard approval, deferred render progress, take in/out selection, timeline,
9:16 video/CapCut and publish package, using a fake window.vidflow API. Additional
coverage checks secret suppression, owner status, validation errors, cancel,
redo and budget/settings actions. Service/MCP exact command-set tests were
extended for the new commands. Tests were not run in this revision; Agent Forge
will execute them. See docs/decisions/M8.5-workspace-status.md for delegations,
limitations and commands.
